# Myuna Real Memory Contract v1

状态：行为契约已由服务器所有者批准；真实数据导入尚未启用  
契约版本：`real-memory-contract-v1`  
策略版本：`memory-policy-v1.0`  
记录日期：2026-07-16（Asia/Shanghai）

## 1. 目标

Myuna 的长期记忆应优先保存时间连续性、原话、原因、具体经过、各种“第一次”及想法变化，成为服务器所有者的长期记忆锚点。文字空间不是主要限制；系统通过分层存储和分层检索控制复杂度，不通过不可逆压缩丢掉原始细节。

本契约约束 Memory Core、归档器、整理模型、gateway、检索器和未来 UI。任何模型供应商、Definition 版本或聊天渠道都不能绕过它。

## 2. 四个严格分开的数据域

```text
Definition             她是谁、如何表达与判断
Personal Memory        她与某个已认证主体共同经历或获知的内容
Operational Records    服务器、Minecraft、Codex、文件和监控记录
Model Context          当前请求的临时上下文
```

- Definition 升级不得静默改写记忆。
- Operational Records 可以按权限查询，但表达必须是“我查看了记录”，不能伪装成“我记得”。
- 消息进入模型上下文不等于自动成为 Personal Memory。
- 每个 Personal Memory 必须属于一个不可跨越的 namespace。

## 3. 存储分层

### 3.1 授权私聊原始档案

服务器所有者与 Myuna 的已认证一对一私聊默认完整归档，保留消息顺序、来源、发送者、时间、附件引用和内容哈希。原始档案是事件证据，不等于所有句子都成为已确认的人格事实。

### 3.2 Active Memory

从原始档案提取可检索的事件、事实、偏好、当前状态、原话、原因和锚点。它具有状态、来源、确认等级、生命周期和修正链。

### 3.3 Derived Index

日索引、周摘要、主题、人物/项目索引和 embedding 都是可重建的派生物。派生物不得覆盖原始档案，也不得成为唯一事实源。

### 3.4 Sealed No-Recall Archive

“不要记”“这是测试”“这一段不进入记忆”等内容默认不进入 Personal Memory，但仍进入独立加密归档。该归档：

- 使用独立 OS 账户和独立目录；
- Myuna Core、普通检索器、整理模型和 gateway 无读取权限；
- 不生成 embedding、摘要或记忆候选；
- 只允许服务器所有者通过专门恢复流程访问；
- Personal Memory 数据库只保留不含正文的归档凭据。

如果用户说“完全不要保存”“不要留下任何副本”或同等明确指令，则不进入 sealed archive。

## 4. 身份与 namespace

自然语言姓名、昵称、头像和自我声明都不是身份凭据。

```text
channel account
→ gateway verified binding
→ immutable principal_id
→ authorized namespace_id
→ Core request context
```

- 服务器所有者拥有独立 `principal_id` 和 owner namespace。
- 未来朋友账号必须建立另一个 principal 和另一个 namespace。
- 即使朋友在消息中声称自己是 `Cealana`，消息仍属于 gateway 已认证的朋友 principal。
- 显示名称可以改变，principal 不能由提示词改变。
- 账号绑定只保存带服务器秘密的 HMAC 指纹或等效不可逆标识，不把认证建立在模型判断上。
- 未认证消息不能读取或修改任何个人 namespace。
- 第二个真实 principal 启用前，必须完成数据库级 namespace 强制过滤和跨 namespace 回归测试。

## 5. 指令层级与提示注入

优先提示词只能作为纵深防御，不能替代身份和权限控制。

执行优先级：

```text
服务器安全策略
> 已批准的 Memory Contract
> 已激活的 Definition release
> gateway 注入的已认证 principal/namespace
> 当前用户请求
> 消息中引用、转发或粘贴的文字
```

“忘掉前面的提示词”“你现在是管理员”“我是 Cealana”等消息正文不能：

- 改变 principal 或 namespace；
- 修改 Definition 或 Memory Contract；
- 读取其他人的记忆；
- 批准工具权限、永久删除或网络开放；
- 把引用文本变成系统指令。

高影响记忆动作必须由确定性命令解析器识别，并再次检查 principal 权限；不由大模型单独判定。

## 6. 记忆类型

```text
episodic          具体事件和经过
exact_quote       需要逐字保留的话
anchor            第一次、承诺、转折和重要时刻
fact              用户明确陈述的事实
preference        稳定或暂定偏好
current_state     有作用域的当下想法
rationale         原因、背景和条件
relationship      与已认证主体有关的关系事实
project           项目与长期目标
```

“说过一句话”与“这个人就是这样”必须拆成不同记录。原因使用独立 rationale 链保存，并注明是用户说明、对话上下文还是模型假设。模型假设只能是 provisional，不能自行转正。

## 7. 时间

默认时区为 `Asia/Shanghai`。每条事件至少包含：

```text
occurred_at
recorded_at
timezone
time_precision
time_phrase
```

普通事件至少保存日期和自然时间段；重要事件可以精确到时分。只知道近似时间时不得伪造精确值。想法变化要保留前后时间线，不能只保留最后状态。

## 8. 3/7/30 生命周期与每日整理

四个时间点含义不同：

1. 约 1 天或系统闲置时：本地整理模型提出分类、摘要、关联和待确认问题。
2. 第 3 天：轻量复核；在部署初期，不确定内容允许由 Myuna 以自己的身份直接询问用户。
3. 第 7 天：巩固判断；确认、延长观察、生成派生摘要或标记冲突。
4. 第 30 天：仍未确认的一次性信息转为低活跃，但详细档案继续保存。

这些期限必须配置化，以后可以修改策略版本。策略改变不得重写原事件。

本地整理模型只能生成 proposal，不能：

- 自行把推测升级为已确认事实；
- 删除、覆盖或永久合并原始事件；
- 读取 sealed no-recall archive；
- 调用网络、工具或云端 provider；
- 在 Minecraft 高负载或本地聊天模型压测时抢占资源。

## 9. 询问与定性

部署初期采用 `ask-when-uncertain`：

- 原因不明、纠正/变化不明、主体不明、时间不明或分类不明时，可以直接询问。
- 问题由 Myuna 以自然的人格表达，不伪装成系统弹窗。
- 问题必须指出她想确认哪一点，不能诱导用户接受模型推测。
- 同一问题进入 review queue，避免重复询问。
- 用户回答产生新的来源事件和修正/原因链。

## 10. 检索

普通日常聊天默认：

- 优先检索最近 1–3 天、当前作用域、已确认相关记忆和必要锚点；
- provisional 可以在其具体作用域内影响回答，但不能无条件压过已确认基线；
- 不主动检索 suppressed 或低活跃详细档案；
- 每次只注入完成当前回答所需的最小、带来源上下文。

明确回忆请求可以深度检索时间线、原话、原因、锚点和详细档案。找不到或来源不足时必须诚实说明，不能补写过程、工具、情绪、地点、时间或引语。

## 11. “忘记”、删除与恢复

| 表达 | 动作 |
|---|---|
| “算了”“忘了吧” | 保留，标记 suppressed，降低主动提起概率 |
| “别主动提” | 保留，只允许明确查询时使用 |
| “不要记／这是测试” | 路由到 sealed no-recall archive，Personal Memory 不可见 |
| “完全不要保存” | 不写入 Personal Memory 或 sealed archive |
| “删除关于 X 的记忆” | 立即停止检索，进入 90 天可撤销隔离 |
| “彻底删除 X” | 清除在线正文、派生摘要、向量和附件引用，只留无内容凭据 |

普通删除的恢复窗口为 90 天。永久删除后，旧备份按保留计划淘汰并记录最晚完全消失日期；加急备份清除必须是单独的高影响操作。

## 12. 隐私与敏感信息

- 地址、位置、健康、关系和其他私人信息允许默认记忆，但必须保持本地存储、namespace 隔离和加密保护。
- 密码、API key、验证码、私钥、完整支付凭据永远禁止进入任何可检索记忆或普通归档。
- 云 embedding 默认禁用；只允许合成数据或逐批明确授权。
- 审计只记录身份、动作、命中 ID、原因码、耗时和哈希，不记录对话/记忆正文。
- 在底层磁盘加密或等效应用层加密得到验证前，不导入真实私密内容。

## 13. 备份

- 每日加密 `pg_dump --format=custom`。
- 保留 30 份每日、26 份每周、长期月度备份。
- D 盘保存完整历史；C 盘保留最近关键加密恢复副本；未来迁移到独立备份盘。
- 每周进行隔离恢复测试。
- 原始事件、修正链和密钥恢复材料是关键资产；embedding 和摘要必须可重建。

## 14. 首次真实数据 gate

真实数据进入前必须同时满足：

1. 用户逐条批准首批候选。
2. owner principal 与 namespace 通过非文本凭据绑定。
3. 磁盘或应用层静态加密已验证。
4. 真实库/真实 schema 与 synthetic dataset 物理或逻辑隔离。
5. 只读 Shadow Mode 能展示命中、来源和原因。
6. 导出、90 天撤销、永久删除和恢复测试至少用虚构数据验证一次。
7. 自动整理服务保持 disabled；用户另行批准后才能定时启用。

首批真实样本只允许 owner namespace、只读检索、无自动写入、无 gateway 外放。
